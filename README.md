# Новостной дайджест-бот для Telegram

Бот раз в день утром собирает свежие новости по трём темам, отбирает 5–8 лучших,
пересказывает их своими словами через Anthropic API и публикует одним постом с
картинкой в Telegram-группу.

**Темы выпуска:**

| Тема | Что попадает |
|---|---|
| 🚕 Рынок такси | приоритет — Пензенская область, затем остальная Россия |
| 🚗 Авто и авторынок | новые модели, продажи, законы, локализация |
| 🚨 Происшествия | только Пенза и область |

Пример поста:

```
Дайджест 30 июля
Такси, авторынок и происшествия за сутки.

🚕 Рынок такси
1. Список такси расширили
В перечень локализованных автомобилей для такси добавили шесть моделей.
АвтоСтат

🚗 Авто и авторынок
2. Tenet T4 уходит с конвейера
Производство кроссовера в Калуге прекращено.
5 колесо
```

## Структура

```
main.py           точка входа: расписание, команды бота, оркестрация прогона
fetcher.py        загрузка RSS, классификация по темам, отбор, дедупликация (SQLite)
scraper.py        разбор страниц изданий, у которых нет RSS
extractor.py      дочитывание полного текста статьи со страницы издания
summarizer.py     обращение к Anthropic API: отбор новостей и сборка текста поста
imagegen.py       картинка к посту: обложка, генерация нейросетью или фото из ленты
sender.py         отправка в Telegram (фото с подписью, длинные посты, ретраи)
tests/            pytest-тесты
requirements.txt  зависимости (requirements-dev.txt — плюс тестовые)
.env.example      шаблон конфигурации
```

## Установка

```bash
git clone <репозиторий>
cd NEWS-TAXI

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # затем заполнить .env
```

Нужен Python 3.10+.

## Настройка

1. **Бот.** Создайте бота у [@BotFather](https://t.me/BotFather), скопируйте токен
   в `TELEGRAM_BOT_TOKEN`.
2. **Группа.** Добавьте бота в группу и дайте ему право писать сообщения.
   Чтобы узнать `TELEGRAM_CHAT_ID`, запустите бота (`python main.py`) и отправьте
   в группе команду `/chatid`. У групп и каналов id отрицательный
   (например `-1001234567890`).
3. **Ключ Anthropic.** Получите ключ в
   [консоли Anthropic](https://console.anthropic.com/) и впишите в
   `ANTHROPIC_API_KEY`.
4. **Администраторы.** В `ADMIN_USER_IDS` перечислите через запятую id
   пользователей. Им разрешена команда `/digest`, и им же приходят сообщения о
   сбоях. Если оставить пусто, `/digest` принимается только из рабочего чата,
   а о сбоях никто не узнает — они останутся только в логе.

Остальные параметры описаны в `.env.example`.

## Запуск

```bash
python main.py               # бот с расписанием: публикует ежедневно в DIGEST_TIME
python main.py --once        # собрать и отправить дайджест сейчас, затем выйти
python main.py --dry-run     # собрать и напечатать пост в консоль, ничего не отправляя
python main.py --check-feeds # проверить доступность всех источников и выйти
python main.py --backup      # сделать резервную копию базы и выйти
```

`--dry-run` не обращается к Telegram и не помечает новости опубликованными,
а картинку сохраняет в файл `DRY_RUN_IMAGE` — удобно проверить настройки и
подобрать источники. Коды выхода: `0` — успех, `1` — сбой (пригодится в cron).

`--check-feeds` печатает таблицу со всеми источниками — и лентами, и сайтами
без RSS: сколько записей отдал каждый, сколько из них подошло по темам и в чём
ошибка, если источник не ответил. Стоит запускать после правки списка.

### Команды в Telegram

| Команда | Действие |
|---|---|
| `/digest` | собрать и отправить дайджест вне расписания (только для админов) |
| кнопки под предпросмотром | подтвердить или отменить выпуск, если включён `PREVIEW_BEFORE_PUBLISH` |
| `/status` | последний прогон, время следующего, число публикаций в базе |
| `/chatid` | id текущего чата — для заполнения `TELEGRAM_CHAT_ID` |
| `/help` | справка |

### Автозапуск (systemd)

```ini
# /etc/systemd/system/news-digest.service
[Unit]
Description=Telegram news digest bot
After=network-online.target

[Service]
Type=simple
User=news
WorkingDirectory=/opt/NEWS-TAXI
ExecStart=/opt/NEWS-TAXI/.venv/bin/python main.py
Restart=always
RestartSec=15

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now news-digest
```

Если держать процесс постоянно не хочется, можно вызывать `--once` из cron —
но тогда не работают ни команды бота, ни автоматический повтор при сбое:

```cron
0 8 * * * cd /opt/NEWS-TAXI && .venv/bin/python main.py --once >> cron.log 2>&1
```

## Как это работает

Прогон состоит из шести шагов:

```
ленты и сайты -> ~20 кандидатов -> модель выбирает 5-8 -> лимит на источник
          -> дочитывание статей -> пересказ моделью -> картинка -> публикация
```

### 1. Источники

Ленты перечислены в `fetcher.py` → `FEEDS`.

| Издание | Как читается |
|---|---|
| penzaobzor.ru, pravda-news.ru, progorod58.ru | собственный RSS |
| penzasmi.ru, riapo.ru, penzainform.ru | разбор страницы со списком новостей (`scraper.py`) |
| autostat.ru, kolesa.ru, 5koleso.ru | собственный RSS (авто) |
| tass.ru, lenta.ru | собственный RSS (федеральные) |

> У penzasmi.ru, riapo.ru и penzainform.ru нет публичного RSS — все типовые
> адреса отдают 404. Раньше они читались через поиск Google Новостей, и это
> давало сразу три неприятности: ссылка вела на редирект Google, полный текст
> статьи по ней не дочитывался, а три источника из задания зависели от одного
> стороннего сервиса. Теперь `scraper.py` разбирает их обычные страницы со
> списком новостей: ссылки прямые, текст доступен. Разбор описан в
> `scraper.SITES` — если издание поменяет вёрстку, правится там.
>
> Дату публикации берём из адреса (`/2026/07/31/`) или из подписи рядом со
> ссылкой. Если её нет, заметка идёт без даты: списки отсортированы от свежих
> к старым, поэтому берутся только первые записи страницы.

**Фолбэк через поиск** (`FALLBACK_FEEDS`) подключается, когда основных лент не
хватило: либо кандидатов меньше `MIN_ITEMS`, либо какая-то из трёх тем осталась
без единой новости. Тогда бот дополнительно запрашивает тематический поиск
Google Новостей.

### 2. Предварительный отбор

1. Из лент и со страниц сайтов берутся записи не старше `MAX_AGE_HOURS`.
2. Тема определяется по ключевым словам (`TAXI_KEYWORDS`, `AUTO_KEYWORDS`,
   `INCIDENT_KEYWORDS`). Слово ищется **по началу слова**, а не как подстрока:
   иначе «лада» находится внутри «вкладам», и новость Минфина уезжает в
   авторубрику. Происшествия учитываются только пензенские, причём чужое ДТП
   не «перетекает» в авторубрику: заметка про аварию без рыночных слов
   (`MARKET_KEYWORDS`) отбрасывается целиком. Тема, заданная лентой, принимается
   на веру только для профильных изданий — поиск возвращает что угодно похожее
   на запрос, поэтому от него требуется совпадение по словам.
3. Каждая новость получает рейтинг: число совпавших ключевых слов, привязка к
   Пензенской области (для такси и происшествий — большой плюс), свежесть,
   штрафы за фолбэк и за ссылку на агрегатор.
4. Дубли отбрасываются: одинаковые ссылки, одинаковые заголовки, заметки об
   одном событии внутри выпуска и сюжеты, о которых мы уже писали за последние
   `STORY_DEDUP_DAYS` дней (сравнение по основам слов — точных хэшей мало,
   другое издание опишет то же событие другими словами).
5. Кандидаты разбираются «по кругу» — по одной лучшей из каждой темы, пока не
   наберётся `CANDIDATE_LIMIT`. Так одно крупное происшествие не занимает весь
   выпуск.

### 3. Финальный отбор моделью

`summarizer.select_best` показывает модели заголовки кандидатов и просит выбрать
лучшие 5–8. Модель убирает то, что эвристики не умеют: заметки об одном событии,
названные по-разному («Wildberries» и «WB»), и случайно зацепившиеся новости не
по теме. Если запрос не удался, берутся первые `MAX_ITEMS` кандидатов — выпуск
всё равно выйдет.

После модели действует ещё одно правило: **не больше `MAX_PER_SOURCE` заметок
от одного издания**. Лишние выбрасываются, а освободившиеся места добираются из
остальных кандидатов, чтобы выпуск не худел. Без этого дайджест легко
превращается в ленту одного сайта — на живых прогонах три из шести новостей
приходили с одного источника.

### 4. Дочитывание статей

Для отобранных новостей `extractor.py` загружает страницу издания и достаёт
основной текст (`trafilatura`, при её отсутствии — встроенный разбор абзацев).
Это заметно улучшает пересказ: в RSS описание нередко состоит из одной фразы,
а у лент Google Новостей его нет вовсе. Отключается через `FETCH_FULL_TEXT=0`.

### 5. Пересказ и публикация

Отобранные новости уходят в Anthropic API (`claude-haiku-4-5-20251001`) одним
запросом. Модель возвращает JSON по схеме (structured outputs): общий заголовок,
вступление, описание обложки и по одному пересказу на новость.

**Ссылки и названия источников подставляет код, а не модель** — так в посте не
может появиться выдуманный URL. Пересказы, которые не удалось сопоставить с
исходной новостью, отбрасываются.

Модель получает текущую дату и время публикации каждой заметки — без этого она
не может корректно написать «сегодня утром» и пишет наугад.

**Пересказ проверяется на копирование.** Требование «своими словами» жило только
в промпте, поэтому теперь описание сравнивается с текстом источника: если в нём
находится цепочка из `COPY_NGRAM` подряд идущих слов оригинала, модель просят
переписать этот пункт. Если и после этого совпадение остаётся, описание убирают
и новость выходит с одним заголовком — лучше так, чем с абзацем, скопированным
у издания.

Пост уходит в Telegram фотографией с подписью; остальные новости — следующими
сообщениями (в подпись к фото Telegram пускает только 1024 символа).

Ссылки по умолчанию уходят в **inline-кнопки** под постом (`LINKS_MODE=buttons`),
так текст читается компактнее; `LINKS_MODE=inline` вернёт ссылку строкой под
каждой новостью. Клавиатура ставится на последнее сообщение выпуска. При
`PIN_DIGEST=1` бот закрепляет пост, предварительно сняв закрепление со
вчерашнего: Telegram держит закреплённые сообщения списком, и без этого за
месяц в шапке чата накопится тридцать дайджестов. Если прав администратора
нет, публикация всё равно состоится, а в лог уйдёт предупреждение.

Новости помечаются опубликованными **только после успешной отправки** — если
Telegram недоступен, тот же материал попадёт в следующий выпуск.

### Предпросмотр перед публикацией

При `PREVIEW_BEFORE_PUBLISH=1` готовый выпуск сначала уходит администраторам —
ровно в том виде, в каком пойдёт в канал, — с кнопками «Опубликовать» и
«Отменить». По кнопке пост уходит в чат; при отмене новости **не** помечаются
опубликованными и вернутся в следующий выпуск.

Если никто не ответил за `PREVIEW_TIMEOUT_MINUTES`, срабатывает
`PREVIEW_ON_TIMEOUT`: по умолчанию `publish` — выпуск уходит сам, потому что
пропущенный дайджест хуже неотсмотренного; `cancel` отменит его.

Режим намеренно выключен по умолчанию и требует заполненного `ADMIN_USER_IDS`.
Если подтверждать некому (список пуст) или бот запущен разово через `--once`,
где нет планировщика для таймаута, выпуск публикуется сразу — с предупреждением
в логе. Ожидающий подтверждения выпуск живёт в памяти: после перезапуска бота
он теряется и будет собран заново.

### При сбое

Если плановый прогон не удался, бот пишет администраторам и планирует повтор
через `RETRY_MINUTES` минут, до `MAX_RETRY_ATTEMPTS` раз. Отсутствие свежих
новостей сбоем не считается: это штатная ситуация, о ней только запись в логе.

**Пропущенный запуск наверстывается.** Планировщик по умолчанию не выполняет
задание, просроченное больше чем на секунду, — перезагрузка сервера в 08:00
стоила бы выпуска за день. Поэтому заданию задан запас `MISFIRE_GRACE_MINUTES`,
а при старте бот сверяется с журналом: если сегодня выпуска не было, а время
публикации уже прошло, дайджест собирается сразу (`CATCH_UP_MISSED=0`
отключает). Срочные посты за выпуск не считаются.

Отдельно отслеживается здоровье лент. Если лента не ответила или вернула ноль
записей `FEED_ALERT_AFTER` прогонов подряд, администраторы получают сообщение —
адреса RSS иногда меняются, и без этого поломка видна только в логах. Ноль
*подходящих* новостей тревогой не считается: издание просто могло сегодня не
писать по нашим темам. Когда лента оживает, счётчик сбрасывается.

## Срочные новости

Между выпусками бот раз в `BREAKING_EVERY_HOURS` часов проверяет ленты и может
опубликовать отдельный короткий пост, не дожидаясь утра. Порог намеренно высокий:

- новость про Пензу и не старше `BREAKING_MAX_AGE_HOURS` часов;
- и при этом либо содержит признаки серьёзного ЧП (`BREAKING_KEYWORDS`:
  погиб, взрыв, эвакуация, обрушение и подобные), либо об этом же событии уже
  написали несколько изданий — это надёжный признак значимости.

Обычное ДТП или бытовой пожар под эти условия не подпадают. Дополнительно
действуют ограничения: не больше `BREAKING_MAX_PER_DAY` постов в сутки и только
в окне `BREAKING_FROM_HOUR`–`BREAKING_TO_HOUR` (ночью бот молчит). Срочные посты
не закрепляются и попадают в ту же базу, поэтому в утренний дайджест повторно
не пойдут. Отключается через `BREAKING_ENABLED=0`.

Порог стоит подстроить под свой канал: список `BREAKING_KEYWORDS` в `fetcher.py`
и условия в функции `find_breaking()`.

## Картинка к посту

Режим задаётся переменной `IMAGE_MODE`:

| Режим | Что делает | Что нужно |
|---|---|---|
| `cover` (по умолчанию) | рисует обложку выпуска: дата, заголовок, темы | ничего |
| `ai` | генерирует иллюстрацию нейросетью Kandinsky по описанию от модели | бесплатные ключи FusionBrain |
| `source` | берёт фото из RSS-вложения главной новости | ничего |
| `off` | публикует пост без картинки | — |

> **Anthropic API изображения не генерирует** — Claude умеет только описать
> сцену словами. Поэтому за саму картинку отвечает либо Pillow (обложка), либо
> внешний сервис. В режимах `ai` и `source` любая ошибка молча откатывается на
> обложку, так что пост не останется без изображения.

Для режима `ai` получите ключи на [fusionbrain.ai/keys](https://fusionbrain.ai/keys)
и впишите в `FUSIONBRAIN_API_KEY` и `FUSIONBRAIN_SECRET_KEY`. Генерация занимает
до минуты — прогон становится дольше. Чтобы подключить другой сервис, достаточно
переписать функцию `generate_image()` в `imagegen.py`.

Внешний вид обложки — палитры, размеры и шрифты — настраивается константами
`_PALETTES`, `WIDTH`/`HEIGHT` и `_FONT_CANDIDATES` в начале `imagegen.py`.

## База данных

SQLite, путь задаётся `DB_PATH` (по умолчанию `digest.db`).

| Таблица | Назначение |
|---|---|
| `published` | хэши URL и заголовка каждой опубликованной новости |
| `runs` | журнал прогонов: время, статус, число новостей |
| `feed_health` | по каждому источнику: когда отвечал, серия сбоев |
| `settings` | небольшое состояние бота (id закреплённого поста) |

Дедупликация проверяет оба хэша: одна и та же заметка не пройдёт повторно ни по
ссылке (с отброшенными `utm`-метками), ни по нормализованному заголовку.
Записи старше `KEEP_HISTORY_DAYS` удаляются автоматически.

```bash
sqlite3 digest.db "SELECT created_at, topic, title FROM published ORDER BY created_at DESC LIMIT 20;"
sqlite3 digest.db "SELECT * FROM runs ORDER BY id DESC LIMIT 10;"
sqlite3 digest.db "SELECT name, broken_streak, last_ok_at, last_error FROM feed_health ORDER BY broken_streak DESC;"
```

## Резервные копии

`digest.db` — это вся память о том, что уже публиковалось. Если база потеряется
при переезде или сбое диска, бот выдаст в эфир новости недельной давности как
свежие. Копия снимается штатным механизмом SQLite, поэтому её можно делать на
работающем боте (простое копирование файла может застать базу в момент записи):

```bash
python main.py --backup            # в BACKUP_DIR, с датой в имени
python main.py --backup /mnt/x.db  # в конкретный файл
```

Копий хранится последние `BACKUP_KEEP`, старые удаляются. Ежедневно — из cron:

```cron
30 3 * * * cd /opt/NEWS-TAXI && .venv/bin/python main.py --backup >> backup.log 2>&1
```

## Логи

Пишутся одновременно в файл `LOG_FILE` (по умолчанию `bot.log`, ротация по 2 МБ,
5 файлов) и в stderr. Уровень задаётся `LOG_LEVEL` (`DEBUG` показывает, какие
заметки отбрасываются как дубли).

**Секреты из логов вычищаются.** Токен бота и ключи API затираются и в
сообщениях, и в трейсбеках — сетевые ошибки Telegram несут внутри URL вида
`api.telegram.org/bot<токен>/sendMessage`, а файл лога обычно лежит без всякой
защиты. Помимо значений из конфига срабатывают шаблоны, так что затирается и
токен, который в `.env` не прописан.

## Проверки в CI

`.github/workflows/checks.yml` гоняет тесты на каждый push и раз в неделю
проверяет ленты. Если какая-то перестала отвечать, workflow заводит issue с
меткой `feeds` (или дописывает комментарий к уже открытой) — так о смене адреса
становится известно до того, как выпуск обеднеет. Проверка лент не требует
никаких ключей.

## Настройка под себя

**Добавить источник** — в `fetcher.py`, список `FEEDS`:

```python
Feed("Название", "https://example.ru/rss", topic=TOPIC_AUTO, region="penza")
```

`topic` можно не указывать — тогда тема определится по ключевым словам;
`region="penza"` помечает издание как местное.

**Расширить тематику** — списки `TAXI_KEYWORDS`, `AUTO_KEYWORDS`,
`INCIDENT_KEYWORDS`, `PENZA_KEYWORDS`. Указывайте основу слова («автомобил»,
а не «автомобиль»): совпадение ищется по началу слова, поэтому «автомобил»
поймает и «автомобили», и «автомобилях».

**Изменить приоритеты** — функция `score()` в `fetcher.py`.

**Изменить стиль постов** — `DIGEST_SYSTEM_PROMPT` в `summarizer.py`;
правила отбора — `SELECT_SYSTEM_PROMPT` там же.

## Что стоит иметь в виду

- Классификация по ключевым словам — эвристика, но грубые промахи подчищает
  модель на шаге финального отбора. Списки слов всё равно стоит править под себя.
- RSS-адреса изданий иногда меняются. Недоступная лента не роняет прогон —
  в лог пишется предупреждение, дайджест собирается из остальных источников,
  а после `FEED_ALERT_AFTER` прогонов подряд приходит сообщение админам.
  Так же ведут себя недоступная страница статьи и сбой генерации картинки.
- Склейка сюжетов сравнивает основы слов в заголовках. Если издания называют
  объект совсем по-разному («Wildberries» и «WB»), внутри одного выпуска дубль
  подчистит модель, а вот межвыпускная проверка такую пару может пропустить.
- Некоторые издания закрыты антиботом и отдают вместо ленты страницу проверки
  (так вёл себя quto.ru, поэтому в списке его нет).
- Стоимость: два запроса к Haiku 4.5 за прогон, суммарно примерно 8–12 тысяч
  входных и до 2 тысяч выходных токенов — доли цента в день.
