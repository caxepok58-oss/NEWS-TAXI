# Новостной дайджест-бот для Telegram

Бот раз в день утром собирает свежие новости по трём темам, отбирает 5–8 лучших,
пересказывает их своими словами через Anthropic API и публикует одним постом в
Telegram-группу.

**Темы выпуска:**

| Тема | Что попадает |
|---|---|
| 🚕 Рынок такси | приоритет — Пензенская область, затем остальная Россия |
| 🚗 Авто и авторынок | новые модели, продажи, законы, локализация |
| 🚨 Происшествия | только Пенза и область |

Пример поста:

```
Дайджест 30 июля
Такси, авторынок и происшествия за сутки.

🚕 Рынок такси
1. Список такси расширили
В перечень локализованных автомобилей для такси добавили шесть моделей.
АвтоСтат

🚗 Авто и авторынок
2. Tenet T4 уходит с конвейера
Производство кроссовера в Калуге прекращено.
5 колесо
```

---

## Структура

```
main.py           точка входа: расписание, команды бота, оркестрация прогона
fetcher.py        загрузка RSS, классификация по темам, отбор, дедупликация (SQLite)
summarizer.py     обращение к Anthropic API и сборка текста поста
sender.py         отправка в Telegram (разбиение длинных постов, ретраи)
requirements.txt  зависимости
.env.example      шаблон конфигурации
```

## Установка

```bash
git clone <репозиторий>
cd NEWS-TAXI

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # затем заполнить .env
```

Нужен Python 3.10+.

## Настройка

1. **Бот.** Создайте бота у [@BotFather](https://t.me/BotFather), скопируйте токен
   в `TELEGRAM_BOT_TOKEN`.
2. **Группа.** Добавьте бота в группу и дайте ему право писать сообщения.
   Чтобы узнать `TELEGRAM_CHAT_ID`, запустите бота (`python main.py`) и отправьте
   в группе команду `/chatid`. У групп и каналов id отрицательный
   (например `-1001234567890`).
3. **Ключ Anthropic.** Получите ключ в
   [консоли Anthropic](https://console.anthropic.com/) и впишите в
   `ANTHROPIC_API_KEY`.
4. **Права на ручной запуск.** В `ADMIN_USER_IDS` перечислите через запятую
   id пользователей, которым разрешена команда `/digest`. Если оставить пусто,
   команда принимается только из чата `TELEGRAM_CHAT_ID`.

Остальные параметры (время публикации, часовой пояс, размер выпуска, пути к базе
и логам) описаны в `.env.example`.

## Запуск

```bash
python main.py             # бот с расписанием: публикует ежедневно в DIGEST_TIME
python main.py --once      # собрать и отправить дайджест сейчас, затем выйти
python main.py --dry-run   # собрать и напечатать пост в консоль, ничего не отправляя
```

`--dry-run` не обращается к Telegram и не помечает новости опубликованными —
удобно для проверки настроек и подбора источников.

### Команды в Telegram

| Команда | Действие |
|---|---|
| `/digest` | собрать и отправить дайджест вне расписания (только для админов) |
| `/status` | последний прогон, время следующего, число публикаций в базе |
| `/chatid` | id текущего чата — для заполнения `TELEGRAM_CHAT_ID` |
| `/help` | справка |

### Автозапуск (systemd)

```ini
# /etc/systemd/system/news-digest.service
[Unit]
Description=Telegram news digest bot
After=network-online.target

[Service]
Type=simple
User=news
WorkingDirectory=/opt/NEWS-TAXI
ExecStart=/opt/NEWS-TAXI/.venv/bin/python main.py
Restart=always
RestartSec=15

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now news-digest
```

Если держать процесс постоянно не хочется, можно не использовать встроенное
расписание, а вызывать `python main.py --once` из cron:

```cron
0 8 * * * cd /opt/NEWS-TAXI && .venv/bin/python main.py --once >> cron.log 2>&1
```

В этом режиме команды бота (`/digest`, `/status`) работать не будут.

## Как это работает

### 1. Источники

Ленты перечислены в `fetcher.py` → `FEEDS`.

| Издание | Как читается |
|---|---|
| penzaobzor.ru, pravda-news.ru, progorod58.ru | собственный RSS |
| penzasmi.ru, riapo.ru, penzainform.ru | через site-запрос к Google Новостям |
| autostat.ru, kolesa.ru, 5koleso.ru | собственный RSS (авто) |
| tass.ru, lenta.ru | собственный RSS (федеральные) |

> У penzasmi.ru, riapo.ru и penzainform.ru нет публичного RSS (все типовые
> адреса отдают 404), поэтому они читаются через ленту поиска Google Новостей
> с фильтром `site:`. Google отдаёт ссылку на свой редирект, а не на издание
> напрямую: в браузере и в Telegram она открывается нормально, но при прочих
> равных бот предпочтёт заметку с прямой ссылкой (небольшой штраф в рейтинге).

**Фолбэк через поиск** (`FALLBACK_FEEDS`) подключается, когда основных лент не
хватило: либо кандидатов меньше `MIN_ITEMS`, либо какая-то из трёх тем осталась
без единой новости. Тогда бот дополнительно запрашивает тематический поиск
Google Новостей.

### 2. Отбор

1. Из лент берутся записи не старше `MAX_AGE_HOURS`.
2. Тема определяется по ключевым словам (`TAXI_KEYWORDS`, `AUTO_KEYWORDS`,
   `INCIDENT_KEYWORDS`). Происшествия учитываются только пензенские.
3. Каждая новость получает рейтинг: число совпавших ключевых слов, привязка к
   Пензенской области (для такси и происшествий — большой плюс), свежесть,
   штрафы за фолбэк и за ссылку на агрегатор.
4. Дубли отбрасываются: одинаковые ссылки, одинаковые заголовки и заметки об
   одном событии (сравнение по основам слов — «Пожар на складе локализован» и
   «Для тушения пожара на складе прибыл вертолёт» считаются одним сюжетом).
5. Новости разбираются «по кругу» — по одной лучшей из каждой темы, пока не
   наберётся `MAX_ITEMS`. Так одно крупное происшествие не занимает весь выпуск.

### 3. Пересказ

Отобранные новости уходят в Anthropic API (`claude-haiku-4-5-20251001`) одним
запросом. Модель возвращает JSON по схеме (structured outputs): общий заголовок,
вступление и по одному пересказу на новость.

**Ссылки и названия источников подставляет код, а не модель** — так в посте не
может появиться выдуманный URL. Пересказы, которые не удалось сопоставить с
исходной новостью, отбрасываются.

В системном промпте модель прямо просят пересказывать своими словами, не
копировать формулировки источника и не додумывать факты, которых нет в исходном
описании.

### 4. Публикация и дедупликация

Пост уходит в Telegram с HTML-разметкой; при превышении лимита в 4096 символов
он разбивается на несколько сообщений по границам абзацев.

Новости помечаются опубликованными **только после успешной отправки** — если
Telegram недоступен, тот же материал попадёт в следующий выпуск.

## База данных

SQLite, путь задаётся `DB_PATH` (по умолчанию `digest.db`).

| Таблица | Назначение |
|---|---|
| `published` | хэши URL и заголовка каждой опубликованной новости |
| `runs` | журнал прогонов: время, статус, число новостей |

Дедупликация проверяет оба хэша: одна и та же заметка не пройдёт повторно ни по
ссылке (с отброшенными `utm`-метками), ни по нормализованному заголовку.
Записи старше `KEEP_HISTORY_DAYS` удаляются автоматически.

Полезные запросы:

```bash
sqlite3 digest.db "SELECT created_at, topic, title FROM published ORDER BY created_at DESC LIMIT 20;"
sqlite3 digest.db "SELECT * FROM runs ORDER BY id DESC LIMIT 10;"
```

## Логи

Пишутся одновременно в файл `LOG_FILE` (по умолчанию `bot.log`, ротация по 2 МБ,
5 файлов) и в stderr. Уровень задаётся `LOG_LEVEL` (`DEBUG` показывает, какие
заметки отбрасываются как дубли).

## Настройка под себя

**Добавить источник** — в `fetcher.py`, список `FEEDS`:

```python
Feed("Название", "https://example.ru/rss", topic=TOPIC_AUTO, region="penza")
```

`topic` можно не указывать — тогда тема определится по ключевым словам;
`region="penza"` помечает издание как местное.

**Расширить тематику** — списки `TAXI_KEYWORDS`, `AUTO_KEYWORDS`,
`INCIDENT_KEYWORDS`, `PENZA_KEYWORDS`. Слова сравниваются по вхождению
подстроки, поэтому указывайте основу («автомобил», а не «автомобиль»).

**Изменить приоритеты** — функция `score()` в `fetcher.py`.

**Изменить стиль постов** — `SYSTEM_PROMPT` в `summarizer.py`.

## Что стоит иметь в виду

- Классификация по ключевым словам — эвристика: изредка возможны как пропуски,
  так и попадание слабо релевантной заметки. Списки слов правятся под задачу.
- Склейка заметок об одном событии тоже эвристическая. Если издания называют
  объект по-разному («Wildberries» и «WB»), обе заметки могут попасть в выпуск;
  отбор «по кругу» ограничивает такой сюжет одной темой выпуска.
- RSS-адреса изданий иногда меняются. Недоступная лента не роняет прогон —
  в лог пишется предупреждение, дайджест собирается из остальных источников.
- Стоимость: один прогон — примерно 3–6 тысяч входных и до 1,5 тысяч выходных
  токенов Haiku 4.5, то есть доли цента в день.
